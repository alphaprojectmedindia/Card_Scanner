# Render Deployment Guide – Digital Share

This guide walk you through deploying the Digital Share backend API and PostgreSQL database on Render.

---

## Deployment Options

You can deploy using either:
1. **Method A: Render Blueprint (Recommended)** – Fully automated using `render.yaml`.
2. **Method B: Manual Dashboard Setup** – Creating the database and web service step-by-step.

---

## Method A: Render Blueprint (Recommended)

Render Blueprints let you declare and manage multiple resources (Web Service + Managed Database + Persistent Disk) as code.

### Step 1: Connect GitHub / GitLab Repository
1. Log in to [Render Dashboard](https://dashboard.render.com).
2. Click **New +** in the top navigation bar and select **Blueprint**.
3. Connect your Git repository containing `render.yaml`.

### Step 2: Configure Blueprint Parameters
1. Render will read `render.yaml` and display the planned resources:
   - **Database**: `digital-share-db` (PostgreSQL 16)
   - **Web Service**: `digital-share-api` (Docker runtime)
   - **Persistent Disk**: `digital-share-uploads` (1 GB mounted at `/app/uploads`)
2. Under the environment variables prompt:
   - Enter your `Gemini__ApiKey` (from Google AI Studio).
   - `Jwt__SecretKey` is automatically generated by Render.
   - `DATABASE_URL` is automatically wired to `digital-share-db`.
3. Click **Apply**.

### Step 3: Apply Database Migrations
Once the database is provisioned:
1. From the Render Dashboard, navigate to **PostgreSQL -> digital-share-db**.
2. Copy the **External Database URL** or **PSQL Command**.
3. Run the idempotent migration script from your local machine:
   ```bash
   psql "<EXTERNAL_DATABASE_URL>" -f backend/DigitalShare.Api/render-database-migration.sql
   ```
4. Verify the database tables:
   ```sql
   SELECT table_name FROM information_schema.tables WHERE table_schema = 'public';
   -- Expected: 18 tables including __EFMigrationsHistory, UserProfiles, ScanJobs, RefreshTokens
   ```

### Step 4: Verify Deployment
1. Navigate to the `digital-share-api` service dashboard.
2. Verify the service shows **Live**.
3. Test the health endpoint:
   ```bash
   curl -i https://digital-share-api.onrender.com/health
   # Expected output: HTTP/1.1 200 OK
   ```

## Method B: Manual Dashboard Setup

If you prefer configuring resources individually:

### Step 1: Create PostgreSQL Database
1. In Render Dashboard, click **New + -> PostgreSQL**.
2. Settings:
   - **Name**: `digital-share-db`
   - **Database**: `digital_share_db`
   - **User**: `digital_share_user`
   - **Region**: `Singapore` (or region closest to your users)
   - **PostgreSQL Version**: `16`
   - **Plan**: `Starter` (or Free for testing)
3. Click **Create Database**.
4. Once created, note the **Internal Database URL** (e.g. `postgresql://...dpg-xxxx:5432/...`) and **External Database URL**.

### Step 2: Apply Migrations
Connect to the database via `psql` using the **External Database URL** and execute:
```bash
psql "<EXTERNAL_DATABASE_URL>" -f backend/DigitalShare.Api/render-database-migration.sql
```

### Step 3: Create Web Service
1. Click **New + -> Web Service**.
2. Connect your repository.
3. Settings:
   - **Name**: `digital-share-api`
   - **Region**: Match the database region (`Singapore`).
   - **Runtime**: `Docker`
   - **Dockerfile Path**: `./backend/DigitalShare.Api/Dockerfile`
   - **Docker Build Context Directory**: `.`
   - **Plan**: `Starter`
   - **Health Check Path**: `/health`

### Step 4: Attach Persistent Disk
1. Scroll down to **Disks** and click **Add Disk**.
   - **Name**: `digital-share-uploads`
   - **Mount Path**: `/app/uploads`
   - **Size**: `1 GB`

### Step 5: Configure Environment Variables
Add the variables documented in [docs/RENDER_ENVIRONMENT_VARIABLES.md](file:///d:/digital_share/docs/RENDER_ENVIRONMENT_VARIABLES.md):
- `ASPNETCORE_ENVIRONMENT`: `Production`
- `DATABASE_URL`: Paste the **Internal Database URL** from Step 1.
- `Jwt__Issuer`: `DigitalShare.Api`
- `Jwt__Audience`: `DigitalShare.MobileApp`
- `Jwt__SecretKey`: Generate a 32+ character random string.
- `Gemini__ApiKey`: Your Google AI Studio key.
- `Storage__Provider`: `Local`
- `Storage__Local__Directory`: `uploads/temp-scans`

Click **Save Changes** and deploy.

## Health Check and Diagnostics

### Service Logs:
In the Render Web Service dashboard, navigate to **Logs**.
Confirm that:
- ASP.NET Core initializes: `Building ASP.NET Core host...`
- The application binds to Render port: `Now listening on: http://0.0.0.0:10000`
- No unhandled startup exceptions occur.

### Live Diagnostic Probing:
```bash
# 1. Health check
curl -f https://<your-subdomain>.onrender.com/health

# 2. Public profile endpoint (non-authenticated check)
curl -i https://<your-subdomain>.onrender.com/api/share/non-existent-id
# Expected: HTTP 404 (indicates ASP.NET Core and routing are fully active)
```
